# 🕵️ auditenv: бухгалтерия, в которой кто-то набедокурил

> Среда для обучения и проверки ИИ-аудиторов (кейс Genesis FinTech). Генератор прячет в компании ошибки,
> агент ищет их инструментами, судья без жалости считает F1. Всё работает без сети, без GPU, на Python 3.11 и одной зависимости (`pytest`).

```
 seed + config
      │
      ▼
 ┌───────────┐  честная бухгалтерия + внесённые ошибки
 │ generator │───────────────┬──────────────────────────────┐
 └───────────┘               │ открытое                      │ закрытое
                             ▼                               ▼
          ┌──────── процесс агента ────────┐     truth.json, provenance.json
          │ политика: list_records,        │     (видит только судья на хосте)
          │ get_record, get_document,      │                  │
          │ calculator, submit(findings)   │                  │
          └───────┬────────────────▲───────┘                  │
   {"name","args"}│                │{"result","error",        │
                  ▼                │ "remaining_steps"}       │
          ┌─────────────── AuditEnv ───────────┐              │
          │ 100 шагов · 60 с · белый список    │              │
          │ файлов · reward для агента = 0     │              │
          └───────────────┬────────────────────┘              │
                          │ submit                            │
                          ▼                                   ▼
                 ┌──────────────────── evaluator ───────────────────┐
                 │ строгая схема → matcher 1:1 → TP/FP/FN → P, R, F1 │
                 │ награда = clip(2·F1 − 1 − 0.002·шаги, −1, 1)      │
                 └───────────────────────────────────────────────────┘
```

## Запуск одной командой

Рабочая директория: корень репозитория (там, где лежит `Makefile`). Сеть не нужна.

```bash
make check            # тесты + 20 открытых эпизодов + организаторские политики через адаптер жюри
make audit            # самооценка по критериям жюри, баллы из 100
# в контейнере без сети:
docker build -t auditenv . && docker run --rm --network none auditenv   # = make check audit
```

Ещё: `make demo` (3 сцены в терминале), `make replay` (HTML «Лента аудита» в `docs/replay.html`),
`make judge` (политики на матрице D01–D20), `make episodes` (пересоздать `data/` по seed).

> Честно: Docker-демон в нашей среде разработки недоступен, поэтому `docker build/run` мы сами не запускали.
> `make check` и `make audit` проходят напрямую на Python 3.11 и 3.13; Dockerfile повторяет те же шаги.

## Что внутри ошибок: четыре типа

| `type` (точное имя) | Что сломано | `affected_ids` (канонический набор) | `claimed_amount_minor` |
|---|---|---|---|
| `duplicate_invoice` | один счёт отражён дважды | оба счёта | сумма счёта |
| `missing_or_partial_allocation` | платёж не закрыл счёт или закрыл не полностью | счёт и платёж | недоприменённая сумма (валюта счёта) |
| `wrong_date_or_fx_rate` | курс взят не на ту дату или не в ту сторону | счёт и платёж | разница зачёта (валюта счёта) |
| `period_cutoff` | проводка перепрыгнула границу периода | счёт | сумма счёта |

Два сценария взаимодействия: `partial_cross_currency_boundary` (кросс-валютный частичный платёж у границы
периода) и `duplicate_with_fx_error` (дубль счёта с неверным курсом). Рядом лежат законные «приманки»:
подписки, возврат → повторный счёт, счета у границы периода, йена без копеек.

## Подключение жюри: `judge_adapter.py`

Тонкий адаптер в корне репозитория (`/app/judge_adapter.py` в контейнере). Обёртка над нашим генератором и средой.

```python
generate_episode(seed, config, output_dir)    # плоский каталог: manifest, ledger, invoices, payments, fx, policy + truth, provenance
env = make_env()                              # reset(seed, config) / step({"name": ..., "args": {...}})
score_episode(episode_dir, findings, inspection_steps) -> dict
```

* `reset(seed, {"mode": "closed", "episode_dir": ..., "team_config": {}})` загружает именно переданный эпизод и
  читает **только** открытые файлы; `mode="train"` без `episode_dir` генерирует эпизод из `team_config`
  (например `{"profile": "hard"}` или `{"errors": {"duplicate_invoice": 2}}`) и отдаёт терминальную награду.
* Первое наблюдение: `{"task", "manifest", "policy", "remaining_steps": 100}`; дальше
  `{"result", "error", "remaining_steps"}`. Ошибка: `{"code", "message"}` без путей, seed и закрытых данных.
* В закрытом режиме `reward` в ответе всегда `0`; истинная награда считается отдельным `score_episode`.
* Таблицы: `ledger`, `invoices`, `payments`, `fx`. Курсы адресуются вычисляемым ID `FX:<дата>:<из>:<в>`
  (колонки id в `fx.csv` нет). Документ счёта/платежа это объект его записи (`DOC-<id записи>`).
* `list_records`: `table`, `cursor` (первый `null`), `limit` (до 50) → `{"records", "next_cursor"}`.
  `get_record`: `table`, `id`. `get_document`: `doc_id`. `calculator`: `expression` → десятичная строка (`"0.3"`).
  `submit`: `findings` → `{"accepted": true}` или ограниченная ошибка структуры (эпизод завершается, награда −1).
* После завершения `step` ничего не меняет и не падает.

### Схема результата `score_episode`

```json
{"tp": 2, "fp": 0, "fn": 0, "precision": 1.0, "recall": 1.0, "f1": 1.0, "return": 0.994}
```
Невалидный submit: `{"tp": null, "fp": null, "fn": null, "precision": null, "recall": null, "f1": null, "return": -1.0}`.

### Формат вывода (`findings.json`)

```json
{"findings": [{"type": "duplicate_invoice", "affected_ids": ["INV-000016", "INV-000020"],
               "evidence_ids": ["DOC-INV-000016", "DOC-INV-000020"],
               "claimed_amount_minor": 549550, "currency": "EUR",
               "explanation": "Тот же клиент, те же позиции, кредит-ноты между счетами нет."}]}
```
Совпадение: тип и валюта точно, `affected_ids` равно каноническому множеству, сумма в пределах τ (по умолчанию 0),
`evidence_ids` содержат полный допустимый набор и все существуют. Лимиты: 30 выводов, по 10 ID, 1000 символов.

## Политики (лестница сложности)

| Политика | Что делает | Средняя награда на 20 эпизодах |
|---|---|---|
| `oracle` | правильный ответ из эталона на стороне судьи | **1.00** |
| `careful` (наше творчество 🎩) | читает книги, пересчитывает курсы по `policy.json`, решает всё | **0.97**, F1 = 1, 0 ложных |
| `careful_dup` | та же, но только дубли | 0.20 (34/34 дублей, 0 из других типов) |
| `reconcile` | «одинаковая сумма у одного клиента = дубль» | −0.54 (100 ложных: подписки и возвраты) |
| `random` | 15 случайных чтений и догадка | −0.99 |
| `flag_all` | 30 выводов «на всякий случай» | −1.00 (600 ложных) |

Через адаптер жюри (матрица D01–D20, закрытый режим, `make judge`): oracle 1.00, careful 0.97, reconcile −0.85,
random −1.00, flag_all −1.00. Разбор причин и повторных проверок: `docs/failure_analysis.md`.

## Что мы добавили сверх задания

* 🎩 **Дотошный аудитор** (`policies/careful.py`) решает задачу, опираясь только на открытые данные и `policy.json`.
  Доказывает: ошибки выводимы без чтения эталона, эталон решаем, а не «угадай, что имел в виду генератор».
* 🧪 **Независимая проверка эталона** (`qa/evidence.py`): каждая из 116 ошибок выводится из открытых данных
  своим набором правил, чистые приманки ошибками не считаются. Валидаторы сами проверены мутациями (28 порчи данных и эталона).
* 🐤 **Канарейки** (`qa/leaks.py`): в закрытые файлы подкладываются метки `CANARY-…`; сканер ищет их и любые
  закрытые значения в наблюдениях, ошибках и `info`.
* 🏴‍☠️ **Галерея взломщиков** (`tests/attackers.py`): 14 способов прочитать эталон из процесса агента
  (open, pathlib, symlink, subprocess, сеть, ctypes…) все заблокированы; зависший и падающий агент не ломают хост.
* 🎬 **Лента аудита** (`docs/replay.html`, `make replay`): шесть политик на одном эпизоде шаг за шагом.
* 📊 **`make audit`**: самооценка по пяти критериям жюри, включая прогон их определений C01–C20, D01–D20,
  matcher 1–20 + M01–M12 и пар P01–P20 на копиях `episode_dir`.

## Структура

```
judge_adapter.py        точки входа жюри
env/                    среда: loader, environment, calculator, harness, изоляция процесса
evaluator/              судья: schema, matcher, metrics, grader
generator/generate_v1.py  генератор (seed → байты файлов)
policies/               oracle, careful, careful_dup, reconcile, random, flag_all, judge_shim
qa/                     валидаторы данных и доказательств, сканер утечек
scripts/                run_policies, run_judge, audit, demo, make_replay
tests/                  792 теста, определения жюри в tests/test_official_*.py
data/{train,dev}/       20 открытых эпизодов (public/ + private/)
runs/                   результаты, траектории (trajectories.jsonl), метаданные запуска
docs/                   design.md, failure_analysis.md, judge_notes.md, env_notes.md, replay.html
```

## Траектории и метаданные запуска

`runs/judge/trajectories.jsonl`: по строке на шаг, поля `episode_id, step, action, observation, reward,
terminated, truncated`; в `observation` только то, что видит политика (проверено сканером). Версии и параметры
запуска: `runs/judge/results.json → meta` (Python, pytest, версия генератора, матрица seed+config);
версия базового образа и зависимостей зафиксирована в `Dockerfile` и `requirements.txt`.

## Ограничения (кратко; подробнее в `docs/failure_analysis.md`)

* Данные синтетические; реальных финансовых данных нет.
* Покрыты 4 типа ошибок и 2 сценария взаимодействия; других сочетаний генератор не делает.
* Дотошный аудитор это правиловая политика (потолок для этой схемы), а не обученная модель. Мы **не**
  утверждаем, что среда улучшает обучение: сравнения «до/после» не проводили.
* Изоляция на уровне Python дополняет, но не заменяет контейнер без сети.
* Допуск суммы по умолчанию: τ = 0.
