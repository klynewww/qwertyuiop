# Разбор сбоев: измерено, объяснено, перепроверено

Все числа получены командами из README на 20 открытых эпизодах (10 train + 10 dev) и на матрице D01–D20
(`make judge`). Воспроизводятся без сети. Мы не утверждаем, что среда улучшает обучение агентов: сравнения
«до и после обучения» мы не делали, это отдельный эксперимент.

## Сбой 1. «Простая сверка» ловится на законных повторах

**Измерение.** Политика `reconcile` группирует счета по (контрагент, сумма, валюта) и объявляет группу дублем.
На 20 открытых эпизодах: 134 группы, из них настоящих дублей 34, ложных выводов 100, средняя награда −0.54;
на чистых компаниях награда −1.00 (она заявляет дубль там, где ошибок нет).

**Причина** (посчитано по тем же данным): из 100 ложных групп 40 это счёт, заново выставленный после
кредит-ноты (законный возврат → повторный счёт), и 60 это повторяющиеся суммы, которые не дубли
(подписки и разные позиции на одну сумму). У дубля по политике компании должны совпадать позиции счёта, и между
счетами не должно быть кредит-ноты.

**Исправление и повторная проверка.** `careful_dup` берёт позиции счёта и учитывает кредит-ноты
(`policies/audit_rules.py: find_duplicates`). Замер: ложных выводов 100 → 0, найдено 34 из 34 дублей,
средняя награда −0.54 → +0.20. Проверка сделана тем же прогоном (`make check`) и закреплена
тестом `tests/test_qa_data.py` (отвлекающие случаи не считаются ошибками).

## Сбой 2. Один тип из четырёх это потолок 0.20 (неустранённый предел, воспроизводимый)

**Измерение.** `careful_dup` находит 34/34 дублей, но 0/28 ошибок распределения платежа, 0/36 ошибок курса/даты
и 0/18 ошибок периода. F1 по эпизодам с ошибками остаётся низким, средняя награда 0.20; полный `careful`
находит 116/116 и даёт 0.97.

**Причина.** Остальные три типа требуют других доказательств: проводки (распределение), курс по дате платежа
из `fx` (пересчёт с ROUND_HALF_EVEN), дата проводки против границы периода в часовом поясе manifest. Один тип
правил их не видит.

**Статус.** Не исправляется намеренно: это ступенька лестницы сложности (oracle 1.00 > careful 0.97 >
careful_dup 0.20 > reconcile −0.54 > random −0.99 ≥ flag_all −1.00). Воспроизведение: `make check`
(таблица «политика × тип ошибки»).

## Сбой 3. Массовая пометка: 600 ложных выводов на 20 эпизодов

**Измерение.** `flag_all` отправляет по 30 выводов (лимит структуры), TP=0, FP=600, награда −1.00 на всех
20 эпизодах, включая чистые. На 5 записях × 4 типах (20 выводов, 1 верный) судья даёт F1 = 2/21 и награду
−871/1050 ≈ −0.83 (тест 12 определений жюри, `tests/test_official_matcher.py`).

**Причина и вывод.** Метрика штрафует ложные выводы через precision, а affected_ids должно совпасть с каноническим
набором точно: «на всякий случай» добавленный ID превращает вывод в FP (тест M02). Исправлять нечего:
это проверенное свойство награды, а не сбой среды.

## Сбой 4 (найден нашим же контролем). Сканер утечек ругался на публичные названия

**Измерение.** После перехода на плоский каталог эпизода (как подаёт жюри) 8 из 20 парных проверок упали:
сканер считал секретом слова «partial», «missing», «wrong_date…» из `provenance.json`, хотя названия четырёх
типов ошибок публичны (они есть в задании агента).

**Причина.** Секретом считалось всё, чего нет в открытых файлах. Названия типов в открытых файлах не лежат.

**Исправление и повторная проверка.** Названия типов и их части занесены в белый список, названия сценариев
взаимодействия остаются секретом (тест `test_leak_of_error_type_name_in_observation_is_found`). Повторный
прогон: 20/20 пар, 0 утечек, 792 теста зелёные. Канарейки (`CANARY-*`, подложенные в закрытые файлы)
по-прежнему находятся.

## Сбой 5 (найден при сверке с определениями жюри). Слишком мягкий судья

**Измерение.** Наш первый судья обрезал пробелы и менял регистр ID/типа и принимал лишние ID в affected_ids,
если они входили в набор доказательств. По определениям жюри так нельзя: вывод `" inv-000012 "` обязан
быть FP.

**Исправление.** Судья переписан: точное сравнение, affected_ids равно каноническому множеству, evidence_ids
содержат полный допустимый набор и все существуют. Проверка: тесты 1–20, M01–M12 (в том числе
47/150, −871/1050, −0.02) и `test_ids_and_type_are_compared_exactly`.

## Честные ограничения (связаны с проверяемыми сценариями)

| Ограничение | Где проверить |
|---|---|
| Данные синтетические, одна компания на эпизод, 4 валюты, период 90 дней; реальных финансовых данных нет | `data/`, `generator/generate_v1.py` |
| Покрыты 4 типа ошибок и 2 сценария взаимодействия (`partial_cross_currency_boundary`, `duplicate_with_fx_error`); других сочетаний в генераторе нет | D16–D20 в `tests/test_official_episodes.py` |
| «Дотошный аудитор» написан по правилам policy.json, это потолок для данной схемы, а не обученная модель; обучения и сравнения до/после нет | `policies/careful.py` |
| Изоляция процесса на уровне Python (audit-hook) не заменяет контейнер; реальная граница это Docker с `--network none`. Docker daemon в нашей среде разработки недоступен, `make docker-check` нами не запускался | `Dockerfile`, `tests/test_process_isolation.py` |
| Допуск суммы по умолчанию τ=0; генератор выставляет `amount_tolerance_minor: 0` во всех ошибках | `truth.json`, тест M08 |
| `fx`-записи адресуются вычисляемым ID `FX:<дата>:<из>:<в>`, колонки id в fx.csv нет | `policy.json: fx_record_id` |
| Лимит времени 60 с проверен на подменяемых часах, а не на настоящем медленном ноутбуке | `test_c18_time_limit_includes_policy_time` |
